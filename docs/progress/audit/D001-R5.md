## B. Numerical-report correction

The defect: D001-R4 reported **59** rejected `javac` class names. The correct count
is **60**.

Why it happened: `non-sealed` was deducted from the rejected total on the argument
that `semantics.md` §1.2b rule 1 rejects it on the character pattern before rule 2
runs. That argument is true about *rule order*. It is false about the *experiment*,
which compiled `non-sealed` and observed `javac` reject it. Reporting it as
untested broke the invariant that accepted outcomes plus rejected outcomes equal
the number of candidates.

The arithmetic, recomputed from the group counts:

```text
51 reserved + 3 literals + 5 restricted identifiers + 1 non-sealed = 60 rejected
11 contextual keywords accepted
60 + 11 = 71 candidates
```

The experiment was **rerun in this session**, not taken from the report. Harness:
each candidate written to `<candidate>.java` and compiled in its own directory;
five ordinary identifiers compiled with the same harness as positive controls.

| Group | n | Accepted | Rejected |
| --- | --- | --- | --- |
| Reserved keywords | 51 | 0 | 51 |
| Contextual keywords | 17 | 11 | 6 |
| Literals `true`/`false`/`null` | 3 | 0 | 3 |
| Controls | 5 | 5 | 0 |
| **Total** | **76** | **16** | **60** |

Programmatic verification over the raw `group|name|status` rows, not by eye:

group counts (accepted, rejected):
  reserved      0  51  n=51

The directive requires an explicit read-only allowlist and forbids treating a
missing `tools` declaration as protection. Both read-only agents now declare one,
and the effect was measured by attempting the prohibited operations.

| Probe | `arara-auditor` | `arara-recovery` | `arara-engineer` |

| Delegate to another agent | no | no | yes, 9 subagent types offered |
| Modified a repository file | **no** | **no** | no (probe wrote only to `/tmp`) |

Effective allowlist semantics observed: `tools: ['read', 'search']` resolves to a
**read-only** set and never to a single tool. In this session's agent host it
resolved to one tool, `view`. In the Copilot CLI harness it resolved to five:
`view`, `rg`, `glob`, `skill`, `sql`. In both cases the set contains no file
writer, no shell, and no delegation, and in both cases the capability boundary is
the same: the agent can read and search, and cannot change the repository. The
earlier statement that the aliases "collapse to a single `view` tool" was true only
of the agent host and is corrected here. Adding `edit`, `execute`, or `agent` is
what materialises the write, shell, and subagent tools.

The auditor's own report adds a useful negative control: it could not run `git`,
`curl`, or `gh` even though the environment metadata names those binaries as
available. The allowlist therefore wins over the ambient environment, and a
"read-only" claim is only true when the allowlist is explicit.

Limitations: this measures one VS Code client version. A future version could
rename or regroup tools, which would silently change what a given alias grants. No
mechanism in this repository detects that, so the verification must be repeated
after a client upgrade. Class: `VERIFIED` for the observed behaviour,
`UNVERIFIED` for durability across client versions.
