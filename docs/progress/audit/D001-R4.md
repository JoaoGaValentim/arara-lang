### 6.1 Defect found in the configured limits

The user configuration sets `maxInputTokens: 1048576` **and**
`maxOutputTokens: 30000`. The provider enforces `prompt_tokens + max_tokens <=
1048576`, so a maximally filled input leaves no room for output: a request with a
full context and a 30 000-token completion is rejected.

Measured boundary: `max_tokens: 1048545` succeeds with a 31-token prompt;
`1048546` fails. That gives `1048576 − 31 = 1048545`, confirming the constraint is
a sum, not two independent caps.

Recommended user-level values, consistent with the directive's candidate and with
the measurement:

```jsonc
"maxInputTokens": 1018576,
"maxOutputTokens": 30000      // 1018576 + 30000 = 1048576
```

`supportsReasoningEffort` currently lists `low, medium, high, xhigh`. The
directive asks for the maximum supported effort; `max` is accepted by the bridge
and is a documented value in the VS Code custom-agent reference. Whether VS Code
forwards `max` through the `chat-completions` reasoning-effort format is
`UNVERIFIED` — the file omits it, so the effective ceiling is `xhigh`.

This file is **user-level configuration and is not committed**. It was inspected
and reported, not rewritten, because it is outside the repository and the
directive forbids committing credentials or user-specific configuration.
